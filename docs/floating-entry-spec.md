# Header 入口注入兜底与悬浮框入口 Spec

## 1. 背景

「分组动态」的唯一入口是注入到站点 Header 的导航条目（见 `grouped-feed-extension-spec.md` §4.2）。该注入强依赖站点 Header 的 DOM 结构，历史上已经因为站点前端重构（2025 年 Header 改版）整段失效一次。

需要解决两个问题：

1. 入口位置调整：入口应落在「大会员」之后、「消息」之前（与站点原生导航顺序更贴合）。
2. 注入失效时不能让功能彻底不可达：需要一个可拖动、位置可持久化的悬浮框作为兜底入口，并提供开关让用户主动控制「只保留悬浮框」（关闭注入）或「始终显示悬浮框」。

## 2. 目标与非目标

### 2.1 目标

- Header 入口插入位置改为「大会员」之后、「消息」之前。
- 注入状态可判定、可对外发布，并在注入不可用时提供悬浮框入口。
- 悬浮框支持拖拽、左右边缘吸附、位置持久化、hover 展开、未读提示、点击打开抽屉。
- 设置页新增两个开关，并在「关闭注入」时对「悬浮框常驻」做强制联动。
- 设置改动在已打开页面上实时生效，无需刷新。

### 2.2 非目标

- 不做悬浮框位置的分站点记忆与跨设备同步。
- 不做悬浮框的自定义图标 / 尺寸 / 主题色。
- 不改变入口点击后的行为（仍然是打开右侧抽屉）。
- 不为 Header 注入引入轮询式或全量 `MutationObserver` 监听。

## 3. 术语与状态模型

### 3.1 注入状态

内容脚本内维护单一注入状态：

| 状态 | 含义 | 悬浮框默认是否显示 |
|---|---|---|
| `pending` | 正在等待 Header 条目容器就绪（初始重试预算内） | 否 |
| `injected` | 入口节点已挂在 Header 条目容器中 | 否 |
| `unavailable` | 注入被用户关闭，或重试预算耗尽仍未成功 | 是 |

- 状态变化通过 nav-entry 模块的订阅 API 发布（同 bundle 内直接调用，不引入全局事件）。
- `pending` 期间不显示悬浮框，避免页面刚打开时先闪一个悬浮框再消失。

### 3.2 有效开关值

```
浮层常驻有效值 = 设置.floatingEntryAlwaysVisible || 设置.disableHeaderEntryInjection
```

「关闭注入」一旦开启，「悬浮框常驻」的有效值必然为真；该推导只影响运行时行为与设置页展示，**不回写**用户配置（关闭注入后仍保留用户原本的常驻设置）。

## 4. Header 入口注入

### 4.1 插入位置

- 主路径：定位站点原生「消息」条目，把入口插到它**之前**（即「大会员」之后、「消息」之前）。
- 识别方式：`data-idx="message"`（站点未登录分支会输出该属性）优先，其次匹配条目触发文案 `消息` / `message`。
- 兜底顺序：容器下标 2 之前 → 追加到末尾。

其余结构约束（`.right-entry > .right-entry__main`、`.right-entry__item`、`.right-entry__item-trigger`、`.trigger-icon`、`.trigger-text`、未读 `.red-num`）沿用现有实现，不再变更。

### 4.2 注入时机与重试

- 启动时若「关闭注入」为真，直接进入 `unavailable`，不做任何注入尝试。
- 否则进入 `pending`，沿用现有指数退避重试预算（前 5 次 300ms 间隔，其后翻倍，上限 5s，总预算 30s）。
- 预算内成功 → `injected`；预算耗尽 → `unavailable`。

### 4.3 注入后的保活

进入 `injected` 后，只对入口的父容器做一层**直接子节点** `childList` 观察（`subtree: false`），以覆盖站点局部重渲染：

- 父容器仍在文档中且入口被摘除 → 立即重插，状态保持 `injected`。
- 父容器本身消失 → 状态转为 `unavailable`，并在同一重试预算内继续尝试恢复。

恢复期间状态保持 `unavailable` 不变，只有真正注入成功才切回 `injected`；这样悬浮框不会因为「尝试—失败—再尝试」而反复显隐。

### 4.4 低成本重试触发点

`unavailable`（且未关闭注入）时，以下事件各触发一次注入尝试，成功即回到 `injected`：

- `document.visibilitychange`（页面重新可见）
- 软导航：`history.pushState` / `history.replaceState` / `popstate`

不引入持续的 DOM 全量监听或定时轮询。

### 4.5 开关联动

- 「关闭注入」由关变开：立即移除已注入节点，停止保活观察与重试，状态转为 `unavailable`。
- 「关闭注入」由开变关：重新进入 `pending` 并按 §4.2 重试。

## 5. 悬浮框入口

### 5.1 形态

- 折叠态：圆角胶囊，内容为「分组动态图标 + 未读数字气泡」，高度 36px。
- 展开态（hover）：在折叠态基础上展开「分组动态」文案，数字气泡保持原样。
- 未读数字始终完整显示，不在折叠态退化为纯色点，也不随 hover 改变尺寸；口径与 Header 入口一致（`>99 → 99+`）。
- 未读为 0 时：数字气泡整体隐藏。
- 数字气泡贴在胶囊右上角（`top: -4px; right: -4px`），相对胶囊外溢 4px；吸附右边缘时气泡右缘距视口边缘仍有 8px，不会被裁切，也不需要额外避让。
- 视觉风格与抽屉一致（白底、品牌色描边/图标、轻阴影）。

### 5.2 默认位置

- 首次出现（无持久化位置）：吸附右侧边缘，垂直位置取视口高度的 40%。

### 5.3 拖拽与吸附

- 整块可拖拽，使用 Pointer 事件 + `setPointerCapture`。
- 按下后移动距离 ≤ 4px 视为点击：派发 `TOGGLE_DRAWER` 打开抽屉。
- 拖拽过程中禁用 hover 展开与过渡动画。
- 拖拽结束时吸附判定：
  - 左边缘距视口左侧 ≤ 48px → 吸附 `left: 12px`；
  - 右边缘距视口右侧 ≤ 48px → 吸附 `right: 12px`；
  - 其余情况保持拖拽后的水平位置（自由停放）。
- 展开方向：以「当前中心点在视口左半还是右半」决定向右展开（锚定 left）还是向左展开（锚定 right）；吸附右边缘时必然向左展开，保证贴边不越界。锚定侧随位置一起持久化。

### 5.4 位置持久化

- 存储位置：`storage.local`，键 `bbe:floating-entry-position`。
- 值结构：`{ side: 'left' | 'right'; offset: number; top: number; updatedAt: number }`。
  - `side`：锚定到视口哪一侧；
  - `offset`：折叠态靠近锚定边缘的一侧到该边缘的距离（CSS px）；
  - `top`：折叠态顶边到视口顶部的距离（CSS px）。
- 之所以记录「锚定边 + 偏移」而不是绝对 `left`：吸附右边缘时若记录 `left`，窗口变宽后悬浮框会从右边缘漂走；记录锚定边后位置在任何视口尺寸下都稳定。
- 写入时机：拖拽结束（含吸附结果）。拖拽过程中的移动不写入。
- 读取时机：内容脚本启动、页面尺寸变化后。
- 容错：读取失败、字段缺失或数值不合法时回退默认位置；窗口尺寸变化后做钳制，保证整块不越出视口（上下左右各保留 12px）。
- 所有站点共用同一份位置，不随 `storage.sync` 跨设备。

### 5.5 显隐规则

```
悬浮框可见 = (注入状态 === 'unavailable' || 浮层常驻有效值) && 抽屉当前不可见
```

- 抽屉打开时隐藏悬浮框（抽屉遮罩覆盖全屏，避免出现被遮罩挡住却仍可点的元素），关闭后按上式恢复。
- 抽屉可见性由 DrawerApp 通过新的内容脚本事件对外发布。

## 6. 设置项

设置页「行为设置」区块新增两项（默认均为关闭）：

| 设置项 | 字段 | 默认值 | 说明 |
|---|---|---|---|
| Header 入口注入 | `disableHeaderEntryInjection` | `false` | 关闭后不再注入 Header 导航入口，只保留悬浮框入口。设置页以正向开关呈现（勾选 = 注入），存储字段为反向 |
| 悬浮框常驻 | `floatingEntryAlwaysVisible` | `false` | 开启后即使 Header 入口注入成功也显示悬浮框 |

联动与展示：

- 「Header 入口注入」为关闭状态时，「悬浮框常驻」的复选框显示为**选中且禁用**（不可点击），并显示提示「已因“Header 入口注入”关闭而强制开启」。
- 关闭注入后重新打开注入时，「悬浮框常驻」回到用户原本保存的值（强制值不回写配置）。

生效时机：

- 设置仍由 `SAVE_SETTINGS` 写入 `storage.local` 的 `bbe:settings`。
- 内容脚本通过 `storage.onChanged`（`local` 区、`bbe:settings` 键）实时接收变更并立即应用：注入开/关、悬浮框显隐都会即时变化，不需要刷新页面。

## 7. 存储与事件契约

新增/变更项：

- `ExtensionSettings` 新增 `disableHeaderEntryInjection`、`floatingEntryAlwaysVisible`（布尔，`normalizeExtensionSettings` 中按 `=== true` 归一，缺失即为 `false`，旧配置天然兼容）。
- `STORAGE_KEYS` 新增 `FLOATING_ENTRY_POSITION: 'bbe:floating-entry-position'`。
- `EXTENSION_EVENT` 新增 `DRAWER_VISIBILITY_CHANGED`（DrawerApp → 悬浮框，detail `{ visible: boolean }`）。
- 内容脚本内新增模块：
  - `src/content/entry-settings.ts`：内容侧读取/订阅设置（直接读 `storage.local` 的 `bbe:settings`，与 `debug-console.ts` 已有的 `storage.onChanged` 用法保持一致），并暴露 §3.2 的有效值计算。
  - `src/content/floating-entry.ts`：悬浮框渲染、拖拽、吸附、持久化、显隐。
  - `src/content/nav-entry.ts`：新增注入状态机与订阅 API、开关联动、保活观察、低成本重试触发点。

## 8. 验收标准

1. Header 入口位于「大会员」之后、「消息」之前，且几何尺寸与相邻原生条目一致。
2. 开启「关闭 Header 入口注入」后：Header 不再出现入口，悬浮框必然显示。
3. 关闭注入、且站点 Header 容器 30s 内未就绪时：悬浮框出现。
4. 开启「悬浮框常驻」后：Header 入口注入成功时悬浮框仍然显示。
5. 悬浮框可拖拽；拖到边缘附近会吸附；刷新页面后位置保持；缩小窗口后不越出视口。
6. 悬浮框在折叠态即完整显示未读数字（`>99 → 99+`）；hover 仅额外展开「分组动态」文案；未读为 0 时不显示数字气泡。
7. 点击悬浮框打开抽屉；抽屉打开期间悬浮框隐藏，关闭后恢复。
8. 在设置页改动两个开关后，已打开的 B 站页面无需刷新即生效。
9. 悬浮框位置在 B 站主域与所有子域名之间共享。
10. 消息中心 `https://message.bilibili.com/#/whisper` 与其他 B 站 HTTPS 子域名均加载内容脚本；可识别 Header 时注入导航入口，否则在重试预算耗尽后显示悬浮框。

## 9. 风险与取舍

- 悬浮框默认宽度会随 hover 变化，因此位置持久化只记录折叠态左上角；展开方向由锚定侧决定，避免贴边展开时越界。
- 注入状态机依赖站点类名，若站点再次重构，`unavailable` 会自然兜底到悬浮框，功能不会整体失效。
- 保活观察只监听直接子节点，避免在视频页等高频 DOM 变化场景下引入性能风险。
